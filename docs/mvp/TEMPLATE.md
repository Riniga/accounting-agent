## Purpose

Why are we building this? What problem does it solve, for whom?

## Goals

What value does this create? State it as outcomes, not tasks.

## Context

What exists today that's relevant — the situation this MVP responds to. Link the
architecture doc, prior MVPs, or gap-register rows this follows up on.

## Scope

What is included. Be concrete enough that "is X in scope" has an obvious answer.

## Out of Scope

What is deliberately not included, and why — a scope boundary is only useful if it says no
to something plausible-sounding.

## Acceptance Criteria

How will you know this MVP is actually done? Each criterion should be checkable, not a
restated goal. Verify these for real (measure, test, check the actual system) before
closing the MVP — don't just assert they're met.
